# 比赛演示脚本

## 目标

用一条完整路径展示“提出问题 → 提供依据 → 获取解释 → 采取行动 → 处理失败”，并在每一步说明数据来源和模式。

## 5 分钟流程

1. **打开首页**：说明天气卡片显示实时或示例状态，新闻徽标区分农业农村部原文和本地资料。
2. **进入智能助手**：保持“演示模式”或展示已配置的同源真实模式。切换“诊断”专家，输入作物、症状、生育期和地区；强调信息不足时应继续追问。
3. **添加叶片照片**：Demo 模式展示本地预览并明确“未进行模型识别”；Real 模式等待上传成功后再发送。故意模拟一次上传失败，展示“上传失败，请重试”，重试成功后继续。
4. **查看回答**：如果是 Demo，指出回答是预设内容，不把它当作病名或用药结论；如果是 Real，展示 SSE 进度、来源和停止/重试语义，不宣称模型效果超出实际记录。
5. **使用知识空间工具**：打开用药稀释或种植收益计算器，输入一组示例参数，解释公式和单位；打开本地资料卡，展示阅读弹窗。
6. **失败恢复**：停止一次生成或断开测试代理，说明界面保留已生成正文、显示错误，并可以重新发送；切换专家或新建会话后旧请求不能回写。

## 演示证据

- 终端：`pnpm check`、`pnpm build` 输出。
- 测试：聊天终态/竞态、附件状态、来源标记和 Demo 队列测试。
- 截图：模式徽标、上传失败重试、远程原文链接、本地资料弹窗和工具计算结果。
- 真实平台材料（如要展示）：Agent ID、平台版本、提示词/知识库导出、插件权限、脱敏运行记录和人工复核结果。

## 讲解边界

不要把预设回复、静态天气趋势、Pexels 图片、新闻补齐专栏或前端状态转换描述为模型能力、实时行情、专业诊断或已上线后端。
