# 架构说明

## 请求与展示边界

```text
浏览器 React 页面
  ├─ Zustand chatStore：会话画布、队列、取消、附件状态
  ├─ src/lib/nuwax.ts：同源会话/SSE/历史/上传契约
  ├─ src/lib/weather.ts：定位、Open-Meteo、示例回退
  └─ src/lib/news.ts：农业农村部原文、来源标记、本地资料
          │
          ├─ Demo：src/lib/chat/demo.ts（不发起模型请求）
          └─ Real：/nuwax-api → 开发代理或受控同源网关 → 女娲平台
```

真实模式由 `VITE_NUWAX_MODE=real` 开启。浏览器只知道同源路径和非敏感模式；`NUWAX_API_KEY` 应由开发代理或生产网关读取。当前仓库的 Vite 代理只服务本地开发，不承担生产认证、限流或租户隔离。

## 聊天生命周期

每一轮真实请求都有独立 `AbortController` 和请求代次。创建会话、历史读取、SSE 增量、终态、超时和停止操作在写回 Zustand 前检查请求是否仍属于当前会话。SSE 成功、业务失败、网络错误和 EOF 只允许一个终态；终态后的迟到事件会被忽略。

附件先经历 `uploading → ready | failed`。真实发送只接受带平台 `key` 的 ready 附件；Demo 只保存本地预览，不声称模型看到了图片。组件卸载、移除或提交后释放不再使用的 object URL。

## 发布方式

1. **静态展示**：`pnpm build` 后部署 `dist`，使用 Demo 模式；适合 GitHub Pages 和作品集展示。
2. **本地受控演示**：Vite 开发代理从 `NUWAX_API_KEY` 注入上游请求头，浏览器仍不持有密钥。
3. **生产真实接入**：使用同源 Node/边缘网关实现相同路径契约，并补上认证、会话归属、上传限制、超时取消和审计策略。该网关不在当前前端仓库中。

## 可验证与不可由仓库证明的内容

测试可以证明状态转换、请求取消、SSE 解析、来源标记和本地工具计算。平台 Agent 的提示词、模型版本、知识库覆盖、插件权限、额度、部署状态及农业专业效果需要平台导出、运行记录和人工评测，不能由前端代码推断。
